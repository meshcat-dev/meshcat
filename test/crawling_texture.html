Test notes: texture motion should stay phase-locked with yellow markers

This page tests texture crawling: moving a texture over a surface at a requested world-space speed. The scene uses a glTF conveyor belt and a green comparison box with the same sample texture, but with different UVs, texture transforms, and geometry. Open the sections below for the test rationale and observation guide.

Algorithm features under test
  1. The crawl axis is defined in the body's frame. Rotating the heading rotates the belt, the box, and the selected axis together.
  2. The page integrates a finite real-valued speed into crawl_displacement. The slider samples positive, negative, and zero speeds; negative values reverse the crawl.
  3. The shader accounts for the mapping from texture coordinates to world space, including the underlying UV layout, texture coordinate scale factors, and geometry scale.
How this page exercises those features
  • The glTF conveyor has authored UVs, a glTF node scale, and KHR_texture_transform scale factors that repeat the texture along the belt.
  • The green box uses default box UVs, no texture-coordinate scale factor, a different length, and a non-identity renderable root transform canceled by an inverse child transform.
  • The shared heading node contains both geometries and the yellow reference markers, so the heading control tests that the body-frame axis follows the body.
  • The yellow reference markers provide velocity reference. Although their motion is related to the axis and speed controls, their motion does not depend on the crawling texture feature. They provide an independent witness to the expected motion.
Reading the apparent speed

There is a latent optical illusion inherent in this scene that can affect the perceived speed of the textures.

  • A denser texture pattern can look faster at the same true world-space speed because texture landmarks pass the eye more frequently.
  • The box and glTF file intentionally have different texture density on different faces. Some faces may therefore appear to move at different speeds even when the computed world-space speed is the same.
  • Use the yellow markers as a non-texture motion reference. If the crawl is correct, texture landmarks should stay phase-locked with nearby markers on the corresponding moving face.
  • Start at the default low speed, where the relationship is easiest to see. Once the motion is clear, increase the speed; the same principle should continue to hold.
Controls
  • Speed: changes the finite real speed that is integrated into the displacement. Zero pauses the crawl, and negative values reverse it.
  • Axis: selects the crawl axis in the body frame. Try +Z to inspect the belt's authored wrap, then try +X and +Y to exercise different face directions.
  • Heading: rotates the body. The texture motion should remain consistent relative to the geometry because the selected axis is body-frame, not fixed in world coordinates.
  • Arrow: shows the selected body-frame axis on the conveyor. Its length follows speed magnitude, and its color changes when the speed is negative.
Expected result

Despite the visual differences between the two objects, the intended result is that both textures move at the same requested world-space speed. A mismatch would indicate that some part of the texture-to-world mapping was not accounted for.
